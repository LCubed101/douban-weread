## 今日重点

今天主要没有继续扩展新功能，而是集中处理两个问题：**候选污染**与**不必要确认**。

### 1. PR #74：修复豆瓣候选污染

问题：用户发送《变量》时，豆瓣搜索结果里混入《情绪》《变量2》《变量7》《变量8》，旧逻辑直接把搜索结果当成版本候选。

修复后流程：

```text
豆瓣搜索结果
↓
严格标题过滤
↓
可信候选
↓
Edition Resolution
```

结论：**Search 负责召回，Resolver 负责判断。** 第三方搜索排序不能直接当成最终实体匹配结果。

### 2. PR #75：Explicit Text Fast Path

问题：#74 修复后，《变量》已经能唯一匹配到正确候选，但机器人仍会先发“你想加入的是这本吗？”确认卡，用户需要多点一次。

现在对以下条件启用 fast path：

- 纯文本书名输入
- 唯一候选
- 用户输入与候选标题完全同名
- 无图书 / 影视歧义

命中后：

```text
发送书名
↓
自动检查豆瓣状态
↓
自动加入想读（如果尚无状态）
↓
自动查询微信读书
↓
只返回最终结果
```

### 3. 安全边界保持不变

以下情况仍然保留确认：多版本、副标题或非完全同名、ISBN / URL、OCR 图片、图书 / 影视同名、证据不足。

原则：**确定的事情少问一次，不确定的事情继续 fail closed。**

### 4. 状态保护

Fast Path 继续复用现有 `DoubanWishFlow`：已有想读不重复写入；在读 / 读过保留原状态；无状态才加入想读；豆瓣处理后继续查询微信读书。

真实回归中，《变量》已经是豆瓣想读，系统直接返回已有状态，并成功找到微信读书同一版本。
